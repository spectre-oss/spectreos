# Android XML TextView

Status: Partial XML text rendering with Unicode wrapping, explicit `lineHeight`/`includeFontPadding` (`235..=236`), extended typography (`257`), uniform auto-sizing / DP balanced & `high_quality` line breaking / soft hyphenation / `inter_word` justification (`RULE_TEXT_LAYOUT_EXT = 296`), timed `<animation-list>` compound drawables (`RULE_COMPOUND_ANIMATION_LIST = 295`), and `autoLink`/`textColorLink`/`linksClickable` span highlighting and clicks (`RULE_TEXT_LINKS_SPANS = 306`); full HarfBuzz/ICU shaping, dictionary hyphenation patterns, offline `map` address geocoding, arbitrary runtime `SpannableString`/`ClickableSpan` Java code, and Android device font/pixel parity remain open.

## Scope and variants

Android XML TextView with text, size, horizontal and vertical gravity, wrapping, explicit line breaks, bold/italic style parsing, `fontFamily` weight mapping, explicit `lineHeight` (`RULE_LINE_HEIGHT = 235`), `includeFontPadding` (`RULE_INCLUDE_FONT_PADDING = 236`), extended text layout (`RULE_TEXT_LAYOUT_EXT = 296`: uniform auto-sizing, `breakStrategy`, `hyphenationFrequency`, `justificationMode`), auto-link span detection/styling/clicks (`RULE_TEXT_LINKS_SPANS = 306`: `autoLink`, `textColorLink`, `linksClickable`), timed `<animation-list>` compound drawables (`RULE_COMPOUND_ANIMATION_LIST = 295`), and uppercase transformation (`RULE_TEXT_ALL_CAPS = 218`).

## State and interaction contract

Text may be supplied by XML or overridden by view ID. TextView, CheckedTextView, Button, CheckBox, RadioButton, Switch, ToggleButton, Chronometer, TextClock and DigitalClock support `textColor` color selectors with ordered enabled, pressed, focused, selected, activated, hovered and checked states; selected and activated state is host-controlled. Checked state applies to checkable widgets. Other widgets and theme-based selector values remain unsupported. Wrap-content width for TextView, CheckedTextView, Chronometer and TextClock uses renderer-provided glyph advances and the longest explicit line, including installed compound drawable extents and padding. For multiline text, measurement and wrapping recognize CRLF, CR, LF, vertical tab, form feed, next-line, line separator and paragraph separator consistently. Single-line handling of the non-CR/LF separators remains incomplete. ASCII advances come from the renderer. Non-ASCII text uses one approximate advance per grapheme, so combining marks and joined emoji do not each add a separate advance. Unicode wide graphemes use an approximate one-em advance; other non-ASCII graphemes use 0.6 em. This is a width-category heuristic, not font measurement; kerning and full shaping remain unsupported. Wrap-content height in a vertical LinearLayout accounts for the available width. `minLines`, `maxLines`, `lines`, `lineSpacingExtra`, `lineSpacingMultiplier`, `letterSpacing`, `lineHeight` (`RULE_LINE_HEIGHT = 235`), `includeFontPadding` (`RULE_INCLUDE_FONT_PADDING = 236`) and end ellipsis are supported with approximate font metrics. `textStyle` accepts `normal`, `bold`, `italic`, and `|` combinations (`bold|italic`, `italic|bold`, `normal|italic`), and `android:fontFamily` / `app:fontFamily` / `typeface` accept standard Android family names (`sans-serif`, `sans-serif-light`, `sans-serif-condensed`, `sans-serif-medium`, `sans-serif-black`, `serif`, `monospace`), mapping `sans-serif-medium` and `sans-serif-black` to bold weight and emitting `RULE_TEXT_STYLE_EXT = 257` (Wave 13A) wired end-to-end in Wave 14A onto Wave 13B's `FontFamily::{Sans, Serif, Monospace}` and `TextStyle.italic` multi-face GLES and Canvas 2D rendering (verified by `wave14a_text_style_ext_italic_and_font_family_across_widgets` in [`tests/android_xml.rs`](../../tests/android_xml.rs) and Page-3 Light/Dark captures `bhoo-m3-showcase-page3.png` / `bhoo-m3-showcase-page3-dark.png`; unknown flags such as `underline` remain strictly rejected). `android:tooltipText` (`RULE_TOOLTIP_TEXT = 258`) is also wired in Wave 14A (hover `0.5s` delay + immediate keyboard `Tab` focus reveal even on non-clickable `TextView`, verified by `wave14a_tooltip_text_reveals_on_hover_delay_and_keyboard_focus`). `textAllCaps="true"` and `RULE_TEXT_ALL_CAPS = 218` are supported; uppercase conversion is Unicode-based and does not apply locale-specific mappings. When combined, `lines` overrides `maxLines`, while `minLines` overrides the minimum set by `lines`, following framework resource attribute order. Full Android HarfBuzz/ICU text shaping, dictionary/locale hyphenation patterns beyond soft-hyphenation oversized-word splitting, `autoSizePresetSizes`, `justificationMode="inter_character"`, offline `autoLink="map"` address geocoding, arbitrary runtime `SpannableString`/`ClickableSpan` styling beyond `RULE_TEXT_LINKS_SPANS = 306`, animated marquee and exact device font measurement remain incomplete; wrapping and truncation preserve extended grapheme clusters; multiline end truncation scans the final line once. Wrapping uses Unicode 15 line-break opportunities with grapheme-safe emergency breaks; mandatory Unicode separators, including CRLF, create separate lines. Soft hyphens are shown when selected as a line break and hidden otherwise; inserted hyphens are removed when that line is ellipsized. Locale-specific complex-script tailoring remains incomplete.

### Explicit `lineHeight` and `includeFontPadding` (Wave 7A / Wave 7B)

- **`RULE_LINE_HEIGHT = 235`:** `tools/import-android-layout.py` emits `kind: 235` on text-bearing widgets (`TextView`, `CheckedTextView`, `Chronometer`, `TextClock`, `DigitalClock`, `Button`, `ToggleButton`, `CheckBox`, `RadioButton`, `Switch`, `EditText`, `AutoCompleteTextView`, `MultiAutoCompleteTextView`) when `android:lineHeight` or `app:lineHeight` resolves to a positive `dp`/`dip`/`sp`/`px` value (directly, via `@style`, via `textAppearance`, `@dimen/`, or `?attr/`; `0dp` and non-text containers emit no rule). At runtime (`Node::resolved_line_height` in `codes/libs/ui/libbhoo/src/systems/android/xml/mod.rs`), the explicit value scales by `LayoutState.effective_density() * LayoutState.effective_font_scale()` and clamps to `>= text_size` (and `>= 1.0`), driving wrap-content measurement, multiline line advance (`line_height * line_spacing_multiplier + dp(line_spacing_extra)`), horizontal `LinearLayout` baseline alignment, and text rendering.
- **`RULE_INCLUDE_FONT_PADDING = 236`:** `tools/import-android-layout.py` emits `kind: 236` (`"true"` or `"false"`) on text-bearing widgets when `android:includeFontPadding` is set directly, via `@style`, or via `textAppearance`. At runtime, `"false"` tightens the default line-height factor from `1.34×` (Android themes: `MaterialLight`, `MaterialDark`, `Material3Light`, `Material3Dark`) or `1.5×` (`AndroidTheme::Bhoo`) to `1.18×`, while `"true"` or omission preserves the active theme's factor. Explicit `RULE_LINE_HEIGHT = 235` takes precedence over `RULE_INCLUDE_FONT_PADDING`.

### Extended text layout: uniform auto-sizing, balanced breaking, soft hyphenation & justification (`RULE_TEXT_LAYOUT_EXT = 296`, Wave 21A / Wave 21B)

- **Importer (`tools/import-android-layout.py`):** Validates and resolves `android:breakStrategy` (`simple`/`high_quality`/`balanced`), `android:hyphenationFrequency` (`none`/`normal`/`full`, normalizing `normalFast`/`fullFast` to `normal`/`full`), `android:justificationMode` (`none`/`inter_word`), and dual-namespace `android:`/`app:` `autoSizeTextType` (`none`/`uniform`), `autoSizeMinTextSize`, `autoSizeMaxTextSize`, and `autoSizeStepGranularity` (direct, `@style`, `textAppearance`, `@dimen/`; defaulting uniform range to `12,112,1` sp and rejecting `<= 0`, missing units, or `min > max`), emitting `RelativeRule { kind: 296, anchor: "<break>|<hyphen>|<just>|<auto_spec>" }` on text/button widgets whenever non-default (and omitting rule `296` on defaults or non-text views).
- **Runtime (`codes/libs/ui/libbhoo/src/systems/android/xml/mod.rs`):** Evaluated across `Kind::Text` and `Kind::Button` measurement, baseline calculation, and painting:
  - **Uniform auto-sizing (`resolve_auto_text_size`):** Binary-searches step-quantized text sizes `min + k * step` (clamped to `max`, scaled by `state.sp`) to pick the largest step fitting `avail_w`, `avail_h`, and `max_lines` / `single_line`.
  - **Balanced & high-quality line breaking (`wrap_text_lines_ext`):** Dynamic-programming optimal line breaking minimizing squared slack across wrapped lines (excluding the final line for `"high_quality"`, including the final line for `"balanced"`).
  - **Soft hyphenation (`normal`/`full`):** Splits oversized words across lines with a trailing `'-'` when a word exceeds the available line width.
  - **Inter-word justification (`"inter_word"`):** Distributes remaining horizontal slack evenly across inter-word gaps on non-final wrapped lines in both LTR (left-to-right) and RTL (right-to-left) layout directions while keeping the final line un-stretched.

### Auto-link detection, link styling & clicks (`RULE_TEXT_LINKS_SPANS = 306`, Wave 24A / Wave 24B)

- **Importer (`tools/import-android-layout.py`):** Resolves `android:autoLink` (`none`, `web`, `email`, `phone`, `map`, `all`, and `|`-combined flags normalized to canonical lowercase `web,email,phone,map`, `all`, or `none`, supporting `@string/`), `android:textColorLink` (`#hex`, `@color/` including `<selector>` ColorStateList static default color, `?attr/textColorLink`, `@null`), and `android:linksClickable` (`true`/`false`, `@bool/`, default `true`), both direct and inherited via `@style` or `android:textAppearance`, emitting `RelativeRule { kind: 306, anchor: "<mask>|<link_rgba>|<clickable:0|1>" }` on `TEXT_BEARING_TAGS` whenever `autoLink != "none"` or `textColorLink` resolves to a color (omitted otherwise; invalid flags, colors, theme attrs, or booleans fail compilation with `ValueError`).
- **Runtime (`codes/libs/ui/libbhoo/src/systems/android/xml/mod.rs`):**
  - Exposes `LayoutState.last_clicked_link: Option<String>` recording the most recently clicked link span text (overwritten on each link click) while returning `Some(self.id)` as the view action.
  - Scans painted lines across `Kind::Text` / `Kind::CheckedText` (single-line, multiline, ellipsized, and `inter_word` justified lines via `paint_text_line_with_links` and `paint_justified_line_with_links`) and non-password `Kind::Edit` (`paint_edit_text`) for non-overlapping `web` (`https://`, `http://`, `www.<host>.<tld>` with balanced-bracket punctuation stripping), `email`, and `phone` (`7..=20` digits with optional `+`, balanced `(...)`, and `-`/`.`/` ` separators) spans.
  - Paints matched spans in `link_color` (explicit RGBA or theme `t.primary` fallback) with a density-scaled `1dp` underline honoring horizontal alignment (`start`/`center`/`end`), letter spacing, `inter_word` justification, and RTL layout direction.
  - Defers `container_clickable` when clickable links exist (`has_clickable_text_links`) so clicking a link inside a clickable `TextView` hits the link span first, and registers `Role::Link` hit targets (`anonymous_child_id(id, 42_000 + link_idx)`) when `clickable == 1` (registering zero `Role::Link` targets when `clickable == 0`).
- **Remaining limitations:** Offline `autoLink="map"` address geocoding is not performed (the flag parses cleanly without producing false-positive spans); arbitrary runtime `SpannableString` / `ClickableSpan` / `URLSpan` Java code is outside static XML; `ColorStateList` `textColorLink` resolves to its static default color at import time; and wrapped links are scanned per painted line rather than merged across line breaks.

`android:textAppearance` supports local `@style` resources, pinned built-in Material 3 / Material Components / AppCompat / AOSP `TextAppearance.*` styles, and `?attr/textAppearance*` / `?android:attr/textAppearance*` theme references for TextView, CheckedTextView, Chronometer, TextClock, Button, ToggleButton, CheckBox, RadioButton, Switch, and `Toolbar` title/subtitle appearances. Supported appearance attributes are text size, `normal`/`bold`/`italic` style combinations, `fontFamily` (`android:` and `app:`), color (including supported selectors), `textColorLink`, all-caps, letter spacing, `lineSpacingMultiplier`, `lineHeight` (`android:` and `app:`), `includeFontPadding`, `breakStrategy`, `hyphenationFrequency`, and `justificationMode`. Style inheritance is resolved at import time; attributes directly supplied by the view or its view style override the text appearance. Compound-button text uses the existing single-line control layout; full Android measurement, custom downloadable `@font/` resources, and runtime configuration changes remain open.

TextView supports `drawableLeft`, `drawableRight`, `drawableTop`, `drawableBottom`, `drawableStart`, `drawableEnd`, `app:drawable*Compat`, and `drawablePadding` for local solid XML shapes with explicit dimensions, supported shape selectors, `<animation-list>` timed multi-frame sequences (`RULE_COMPOUND_ANIMATION_LIST = 295`, Wave 21A/21B), or `@null`. Rectangles may have uniform corners; ovals may be elliptical. Non-null start/end shapes and animated compound slots override physical left/right and follow layout direction. Text drawing, wrap-content measurement and baseline calculations reserve space for the shapes/frames and padding. `drawableTint` accepts literal colors and supported enabled, pressed, focused, selected, activated and hovered state selectors; it colors each shape/frame while multiplying the drawable and tint alpha, approximating the default source-in mode. TextView and CheckedTextView support this subset. Explicit `drawableTintMode` supports `src_in`, `src_atop`, `src_over`, `multiply`, `screen` and `add` for solid shapes and animated compound frames; the default is `src_in`. Compound drawable state selectors support solid shapes and @null, with enabled, pressed, focused, selected, activated and hovered states; CheckedTextView also supports checked state. Selector shapes may have different intrinsic sizes. The initially selected shape supplies fixed installed bounds; with `constantSize="true"`, the maximum intrinsic width and height supply those bounds. Later selected shapes render inside the installed bounds, including when the selected state is @null. A selector with no initial intrinsic shape is rejected unless constantSize supplies one.

### Timed `<animation-list>` compound drawables (`RULE_COMPOUND_ANIMATION_LIST = 295`, Wave 21A / Wave 21B)

- **Importer (`resolve_animation_list_drawable` + `decode_animation_list_frames` in `tools/import-android-layout.py`):** Unwraps `<inset>` wrappers with cyclic-reference detection, bundles all frames (PNG, `<vector>`, inline `<shape>`, preserving `android:autoMirrored` `RULE_AUTO_MIRRORED = 255`) into `install_drawables`, preserves frame-0 static fallback rules (`169..=174`), and emits repeatable `RelativeRule { kind: 295, anchor: "<slot>:<oneshot:0|1>|<img_key_0>:<dur_ms_0>,..." }` (`slot` in `start|top|end|bottom|left|right`).
- **Runtime (`paint_compound_drawables` + `select_animation_list_frame` in `codes/libs/ui/libbhoo/src/systems/android/xml/mod.rs`):** Evaluates `f.time()` across `Kind::Text`, `Kind::CheckedText`, `Kind::Button` (including Extended FAB), and `Kind::Edit`/`AutoComplete`/`MultiAutoComplete`, looping (`oneshot = 0`) or clamping on the final frame (`oneshot = 1`), scheduling exact next-frame `f.wake_at(...)` wakeups only when visible inside `f.clip`, applying `drawableTint`/`drawableTintMode` and RTL logical start/end + `autoMirrored` flipping, and freezing strictly on frame `0` with zero wakeup under `MotionPreference::Reduced`.

Static bitmap/vector compound drawables outside `<animation-list>`, `<animated-vector>`/`<animated-selector>` compound drawables, other tint modes, exact drawable gravity, edge compositing and Android text measurements remain open.

## Motion and animation

Static text does not animate. Timed `<animation-list>` compound drawables (`RULE_COMPOUND_ANIMATION_LIST = 295`) advance by frame duration using `f.time()` and clip-gated `f.wake_at()` wakeups (stopping when clipped offscreen or after a `oneshot` sequence finishes; see [motion.md](../motion.md#scheduling-and-lifecycle)).

**Reduced motion:** Static rendering remains unchanged; timed `<animation-list>` compound drawables freeze strictly on frame `0` with no scheduled wakeup or redraw loop.

## Acceptance criteria

- Wrap words and long runs to the available width.
- Preserve explicit line breaks and place following content below the text.
- Check inherited text appearance, direct override and pressed/disabled color selectors.
- Check uniform auto-sizing, DP `balanced`/`high_quality` line breaking, soft hyphenation, and LTR/RTL `inter_word` justification (`RULE_TEXT_LAYOUT_EXT = 296`).
- Check `autoLink` (`web`, `email`, `phone`, `all`, `none`), `textColorLink`, `linksClickable`, `1dp` underline alignment in LTR/RTL and justified text, deferred clickable container handling, and `LayoutState.last_clicked_link` updates (`RULE_TEXT_LINKS_SPANS = 306`).
- Check all four compound drawable positions, start/end RTL placement, reserved text space, and timed `<animation-list>` playback including clip-gated wakeups and reduced-motion freeze (`RULE_COMPOUND_ANIMATION_LIST = 295`).
- Check compound drawable tint on normal, pressed, selected and disabled states without tinting text.
- Compare text layout and font metrics with Android on a device.
