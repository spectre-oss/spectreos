## Scope and variants

`ConstraintLayout` positions and sizes direct children relative to parent edges and sibling edges using explicit directional constraints, bias, helpers, chains, ratios, percentages, baselines, and gone margins. `tools/import-android-layout.py` compiles both `<androidx.constraintlayout.widget.ConstraintLayout>` and `<ConstraintLayout>` into `bhoo::android_xml::Kind::ConstraintLayout` (separate from the earlier fixture-specific `android_reference` bridge).

Supported variants and capabilities:

- Parent (`"parent"`) and sibling (`@id/...` / `@+id/...`) edge anchors on both horizontal and vertical axes (`196..=203`).
- Logical start/end mirroring in right-to-left (RTL) layout direction, including horizontal bias inversion and RTL wrap-content width measurement.
- Horizontal and vertical bias (`0.0..=1.0`, defaulting to `0.5` when opposing edges are constrained) (`204..=205`).
- `0dp` match-constraint sizing (`Size::Dp(v)` with `v <= 0.0`) spanning between two opposing anchors, alongside fixed `dp` (scaled by `LayoutState.density`), `wrap_content`, and `match_parent` sizing.
- End-to-end `Guideline` nodes (`RULE_GUIDE_ORIENTATION = 210`, `RULE_GUIDE_BEGIN = 211`, `RULE_GUIDE_END = 212`, `RULE_GUIDE_PERCENT = 213`): emitted directly by `tools/import-android-layout.py` and solved at runtime for vertical and horizontal zero-extent guidelines positioned by `begin` dp, `end` dp, or `percent` (`0.0..=1.0`) with LTR/RTL horizontal mirroring, emitting no semantic nodes and contributing zero extent to siblings and wrap-content container bounds.
- End-to-end horizontal and vertical bidirectional Chains & Weights (`RULE_CHAIN_STYLE_H = 214`, `RULE_CHAIN_STYLE_V = 215`, `RULE_CONSTRAINT_H_WEIGHT = 216`, `RULE_CONSTRAINT_V_WEIGHT = 217`): emitted directly by `tools/import-android-layout.py` and solved at runtime for `spread` (default), `spread_inside`, and `packed` (with head bias, mirrored in RTL) distribution styles, weighted `0dp`/match-constraint chains (including mixed fixed + weighted members and chains anchored to Guidelines), `goneMargin*` overrides on gone outer/interior neighbors, and `Visibility::Gone` chain member exclusion.
- End-to-end `DimensionRatio` (`RULE_CONSTRAINT_DIMENSION_RATIO = 219`): supports `"W:H"`, `"H,W:H"`, `"W,W:H"`, and positive float ratios (e.g. `"16:9"`, `"H,16:9"`, `"W,4:3"`, `"1.5"`), computing the `0dp` axis from the resolved orthogonal axis (including a second horizontal+vertical pass when a child derives width from height so downstream horizontal siblings follow the resolved width).
- End-to-end percent sizing (`RULE_CONSTRAINT_WIDTH_PERCENT = 220`, `RULE_CONSTRAINT_HEIGHT_PERCENT = 221`): sizes `0dp` children to a `0.0..=1.0` fraction of the available constrained span (centered or biased between anchors).
- End-to-end baseline alignment (`RULE_CONSTRAINT_BASELINE_TO_BASELINE = 222`): aligns a child's vertical position so its `relative_baseline` (text views and buttons) matches the referenced visible sibling's baseline.
- End-to-end gone margins (`RULE_CONSTRAINT_GONE_MARGINS` / alias `RULE_CONSTRAINT_GONE_MARGIN = 223`, extended in Wave 20A/20B): applies `"l,t,r,b,s,e"` dp offsets (or 7-value `"l,t,r,b,s,e,<baseline_dp>"` when `app:layout_goneMarginBaseline` is set; runtime `parse_gone_margins_full` also accepts 5-value `"s,t,e,b,baseline"`, with logical `start`/`end` overriding physical `left`/`right` in LTR and RTL and supporting `0dp` explicit overrides) whenever the targeted sibling anchor has effective visibility `Visibility::Gone`, across individual constraints, chain outer/interior edges, and `RULE_CONSTRAINT_BASELINE_TO_BASELINE = 222` baseline alignment.
- End-to-end enhanced dynamic `Barrier` helpers (`RULE_BARRIER` / alias `RULE_CONSTRAINT_BARRIER = 224`, extended in Wave 18A/18B): tracks the extremal edge (`left`, `right`, `start`, `end`, `top`, `bottom`, with LTR/RTL mirroring for `start`/`end`) across referenced siblings dynamically as runtime text (`LayoutState.text`) or visibility (`LayoutState.visibility`) changes, applies density-scaled direction-signed `app:barrierMargin` (`+margin` for `right`/`bottom`/LTR `end`/RTL `start`; `-margin` for `left`/`top`/LTR `start`/RTL `end`, supporting `@dimen/` and negative dp), honors `app:barrierAllowsGoneWidgets` (default `true` includes `Gone` views' collapsed position; `false` excludes `Gone` views cleanly), collapses to the container start edge if no eligible referenced siblings remain, and emits no semantic nodes.
- End-to-end `Group` visibility propagation (`RULE_GROUP_REFS = 225`): propagates `Visibility::Gone` (collapsing layout space and hiding draw/semantics) and `Visibility::Invisible` (preserving layout space while hiding draw/semantics) from a `Group` helper to all referenced non-helper siblings, while keeping the `Group` itself non-visual.
- End-to-end enhanced `Flow` virtual layout helper (`RULE_FLOW = 232` extended in Wave 18A/18B + `RULE_CONSTRAINT_FLOW_EXT = 292` in Wave 20A/20B): emitted directly by `tools/import-android-layout.py` from `<androidx.constraintlayout.helper.widget.Flow>` and `<android.support.constraint.helper.Flow>` (with `@style` resolution across `FLOW_ATTRS`) and solved at runtime for horizontal (`0`/`h`) and vertical (`1`/`v`) orientations, `none`, `chain` (also lowering `chain2`), and `aligned` wrap modes, density-scaled `flow_horizontalGap` / `flow_verticalGap`, `flow_horizontalStyle` / `flow_verticalStyle` (`spread`, `spread_inside`, `packed`), `flow_horizontalBias` / `flow_verticalBias` (RTL-mirrored horizontally), `flow_horizontalAlign` (`start`, `center`, `end`) / `flow_verticalAlign` (`start`/`top`, `center`, `end`/`bottom`, `baseline`), `flow_maxElementsWrap` (`-1` normalized to unbounded `0`), per-first/last-line chain style & bias overrides (`RULE_CONSTRAINT_FLOW_EXT = 292`: all 8 `flow_first/lastHorizontal/VerticalStyle/Bias` attributes applying `first_*` to line `0` and single-line `Flow`, and `last_*` to line `len - 1` across horizontal/vertical `Flow`, RTL-aware), `Gone` and `Group`-hidden sibling exclusion, LTR/RTL placement, non-visual zero-semantic helper behavior, and resolved bounding-box updates so dependent siblings anchored to the `Flow` (such as `top_toBottomOf="@id/flow"`) position below/beside its final wrapped extent.
- End-to-end circular positioning (`RULE_CONSTRAINT_CIRCLE = 233`): emitted directly by `tools/import-android-layout.py` from `app:layout_constraintCircle` (`"parent"` or `@id/` / `@+id/`), `app:layout_constraintCircleRadius` (dp, default `0`), and `app:layout_constraintCircleAngle` (degrees, default `0`) and solved at runtime center-to-center clockwise from 12 o'clock (`cx = tcx + r * sin(rad)`, `cy = tcy - r * cos(rad)`) with density-scaled radii (`state.dp(radius_dp)`), cycle-guarded chained circular targets, and follow-up axis resolution for dependent siblings.
- End-to-end constrained wrap & min/max size bounds (`RULE_CONSTRAINT_SIZE_BOUNDS = 280`, Wave 18A/18B): emitted from `app:layout_constrainedWidth`/`Height` (including `@bool/` and `@style`) and `app:layout_constraintWidth_min`/`max` & `Height_min`/`max` (including `@dimen/` and `"wrap"` -> `0`). At runtime, clamps dual-anchored `Size::Wrap` children to the available `(high - low).max(0.0)` span when constrained (so wrapped `TextView`s wrap onto multiple lines instead of overflowing past anchors) and applies density-scaled `state.dp(...)` min/max bounds on both constrained `Size::Wrap` and `0dp` match-constraint children (including weighted chain members).
- End-to-end `Layer` helper (`RULE_CONSTRAINT_LAYER = 281`, Wave 18A/18B): emitted from `<androidx.constraintlayout.helper.widget.Layer>` / `<android.support.constraint.helper.Layer>` (`app:constraint_referenced_ids`) alongside any `RULE_VIEW_TRANSFORM = 256`, `RULE_ELEVATION = 193`, `background`, `padding`, and `view_alpha`. At runtime, computes the union bounding box of visible referenced non-helper siblings (excluding `Gone` views), expands chrome by Layer padding, wraps chrome and referenced siblings together inside balanced `PushTransform` (around union center, composing static `RULE_VIEW_TRANSFORM` + runtime `LayoutState::{view_translation, view_scale}`) and `PushLayer` (composing `view_alpha * state.view_alpha`), and paints Layer elevation and background behind referenced siblings without emitting Layer semantics.
- End-to-end `Placeholder` helper (`RULE_CONSTRAINT_PLACEHOLDER = 282`, Wave 18A/18B): emitted from `<androidx.constraintlayout.widget.Placeholder>` / `<android.support.constraint.Placeholder>` (`app:content`, `app:emptyVisibility` / `app:placeholder_emptyVisibility`, default `gone`). At runtime, resolves the target sibling from `LayoutState::placeholder_content` (keyed by placeholder XML ID; empty string clears) falling back to static `app:content`, relocates the bound target to render and accept input/semantics strictly once at the Placeholder's bounds (with Placeholder `Size::Wrap` adopting the target's dimensions), and applies `emptyVisibility` (`gone`, `invisible`, `visible`) when empty.
- End-to-end physical vs. logical horizontal pinning (`RULE_CONSTRAINT_PHYS_FLAGS = 287`, Wave 19A/19B): emitted by `tools/import-android-layout.py` as bitmask `"<bitmask_u8>"` (`1` = physical `Left` without logical `Start`, `2` = physical `Right` without logical `End`; runtime also supports bit `4` = physical horizontal bias and left/right margins / gone margins when both anchors are physical). At runtime, `parse_constraint_phys_flags` honors physical vs. logical pinning across `ConstraintAxis`, horizontal chains, gone margins, and `Flow` helpers in RTL mode while preserving 100% logical RTL mirroring when `287` is absent.
- End-to-end `0dp` match-constraint default sizing (`RULE_CONSTRAINT_DEFAULT_SIZE = 294`, Wave 21A/21B): `tools/import-android-layout.py` validates and resolves `app:layout_constraintWidth_default` and `app:layout_constraintHeight_default` (`"spread"`, `"wrap"`, `"percent"`, direct, `@string/`, or `@style`, strictly rejecting invalid values) into `"<w_def>,<h_def>"` (omitted when both are `"spread"`). At runtime (`parse_constraint_default_size`), on `0dp` match-constraint children (`Size::Dp(v)` with `v <= 0.0`), `"wrap"` measures intrinsic `Size::Wrap` clamped to `<= available_span` and `RULE_CONSTRAINT_SIZE_BOUNDS = 280` bounds with RTL-aware bias (`204`/`205`), and `"percent"` multiplies `220`/`221` by parent inner extent clamped by `280` bounds and positioned via bias even with dual anchors.
- Physical and relative child margins, container padding, `visible` / `invisible` / `gone` visibility (with zero effective extent for `gone` anchors), runtime `LayoutState.density` / `font_scale` scaling, and wrap-content container measurement in both LTR and RTL.

## State and layout contract

Children keep their normal interaction, visibility, state-layer, focus, and action behavior. Container clipping (`android:clipToPadding`, `android:clipChildren`) and explicit `android:layoutDirection` follow the shared `android_xml` container rules. When `!f.any_scroll_dragging()`, visible non-helper higher-z siblings whose `blocks_pointer_for_lower_siblings()` is `true` and whose clipped bounds contain the pointer occlude lower siblings from pointer/wheel events via `Frame::without_pointer_input` ([`composition.rs`](../../src/systems/material/mod.rs), [`android_xml.rs`](../../src/systems/android/xml/mod.rs)) while preserving keyboard focus and key events.

### Axis resolution contract

`constraint_layout_positions`, `constraint_group_visibilities`, `constraint_layout_axis`, `detect_constraint_chains`, `resolve_flow_helpers`, `resolve_circle_constraints`, and `ConstraintAxis` in `codes/libs/ui/libbhoo/src/systems/android/xml/mod.rs` resolve children in coordinated passes:

1. **Group visibility propagation (`225`):** `constraint_group_visibilities` computes the effective visibility table for all direct children before axis solving. Any `Group` (`RULE_GROUP_REFS`) whose own effective visibility is `Gone` forces referenced non-helper siblings to `Gone`; a `Group` with `Invisible` promotes `Visible` referenced siblings to `Invisible` (preserving their layout geometry while skipping draw and semantic emission). Zero-size helpers (`Guideline`, `Barrier`, `Group`) and `Flow` emit no draw commands or semantic nodes; `Flow` retains its computed bounding box for dependent siblings while `Guideline`/`Barrier`/`Group` have zero extent.
2. **Horizontal axis first, vertical axis second, plus width-ratio re-solve (`219`):** Child horizontal intervals `(x, width)` are resolved before vertical intervals `(y, height)` so `wrap_content` vertical measurement (such as wrapped `TextView` height) and height-targeted `DimensionRatio` calculations use each child's resolved width and the active `TextMetrics`. When any non-gone child has a width-targeted `DimensionRatio` (`resolved_ratio_target` returns `RatioTarget::Width`, e.g., `"W,4:3"` with `0dp` width and known height), `constraint_layout_positions` re-runs the horizontal pass with the solved heights and, if any horizontal interval changes, refreshes the vertical pass so sibling constraints downstream of the width-ratio view stay consistent.
3. **Guidelines (`210..=213`) and dynamic Barriers (`224`):**
   - `guideline_position` evaluates vertical guidelines on the horizontal axis and horizontal guidelines on the vertical axis (returning `(origin, 0.0)` on the orthogonal axis), with precedence `begin` -> `end` -> `percent` -> container start (all dp values scaled by `state.dp(...)`) and LTR/RTL horizontal mirroring. When the container wraps on that axis, `end` and `percent` fall back to the container start edge.
   - `barrier_position` evaluates `RULE_BARRIER` / `RULE_CONSTRAINT_BARRIER` on its active axis (`left`/`right`/`start`/`end` horizontally with RTL mirroring for `start`/`end`; `top`/`bottom` vertically), computing the minimum (`left`, `top`, `start` LTR, `end` RTL) or maximum (`right`, `bottom`, `end` LTR, `start` RTL) outer edge across eligible referenced siblings (skipping cyclic references via `visiting`, excluding `Visibility::Gone` siblings when `allows_gone == false` while including collapsed `eff_size = 0.0` positions when `allows_gone == true`), and offsetting the resulting extremum by density-scaled direction-signed `margin_px = state.dp(spec.margin_dp)` (`+margin_px` for max-side barriers, `-margin_px` for min-side barriers). If no eligible referenced siblings remain, the barrier collapses to the container start edge (`origin + extent` in RTL horizontal, otherwise `origin`).
4. **Bidirectional chains & weights (`214..=217`) and physical chain direction (`287`):**
   - `detect_constraint_chains` discovers chains of two or more non-helper siblings connected bidirectionally (`RULE_CONSTRAINT_END_TO_START` <-> `RULE_CONSTRAINT_START_TO_END` horizontally, matching physical vs. logical edge flags on adjacent links; `RULE_CONSTRAINT_BOTTOM_TO_TOP` <-> `RULE_CONSTRAINT_TOP_TO_BOTTOM` vertically) and groups each chain starting at its head.
   - `resolve_chain` reads the chain style (`RULE_CHAIN_STYLE_H` / `RULE_CHAIN_STYLE_V`, defaulting to `Spread`) and bias (`RULE_CONSTRAINT_HORIZONTAL_BIAS` / `RULE_CONSTRAINT_VERTICAL_BIAS`, defaulting to `0.5` and mirrored in RTL unless pinned physically via `RULE_CONSTRAINT_PHYS_FLAGS = 287`) from the chain head, resolves outer anchors on the head and tail (reversing physical order in RTL for logical horizontal chains while preserving left-to-right order for physical horizontal chains), applies `goneMargin*` (`223`) when outer or adjacent chain neighbors are `Gone`, and filters out `Visibility::Gone` chain members (collapsing gone members to `0.0` size at the preceding position).
   - If the chain has both outer anchors and any active member uses `0dp` match-constraint (or `Size::Match` when not wrapping), each match-constraint member receives `parse_chain_weight` (defaulting to `1.0`), splits `(total_span - fixed_total - sum_margins).max(0.0)` proportionally to its weight, and clamps to any `RULE_CONSTRAINT_SIZE_BOUNDS = 280` min/max bounds.
   - Unweighted dual-anchored chains distribute remaining space according to `Spread` (`extra / (n + 1)` gaps), `SpreadInside` (`extra / (n - 1)` interior gaps, or biased single item when `n == 1`), or `Packed` (contiguous items shifted by `extra * bias`).
5. **Edge precedence, gone margins (`223`), physical vs. logical pinning (`287`), and RTL mirroring (non-chain children):**
   - `resolve_edge_info_phys` returns `(edge_coord, target_is_gone)` for `"parent"` or sibling anchors (collapsing `Gone` targets and helpers to `0.0` extent). When `target_is_gone` is true, `parse_gone_margins_phys` substitutes the matching side's gone margin (scaled by `state.dp(...)`, with logical `start`/`end` overriding physical `left`/`right` in LTR and RTL unless physical margins are active via bit `4` with both physical anchors) instead of the regular margin.
   - In LTR (`!state.rtl`), the low (left) edge resolves from `RULE_CONSTRAINT_START_TO_START` or `RULE_CONSTRAINT_START_TO_END` plus leading margin; the high (right) edge resolves from `RULE_CONSTRAINT_END_TO_END` or `RULE_CONSTRAINT_END_TO_START` minus trailing margin; bias uses `raw_bias` clamped to `0.0..=1.0`.
   - In RTL (`state.rtl`), when `RULE_CONSTRAINT_PHYS_FLAGS = 287` is absent (`0`), the low (left) edge resolves from `RULE_CONSTRAINT_END_TO_END` or `RULE_CONSTRAINT_END_TO_START` plus left margin, the high (right) edge resolves from `RULE_CONSTRAINT_START_TO_START` or `RULE_CONSTRAINT_START_TO_END` minus right margin, and horizontal bias mirrors to `1.0 - raw_bias`. When `287` is present, bit `1` keeps `196`/`197` physically pinned to the left edge, bit `2` keeps `198`/`199` physically pinned to the right edge, and bit `4` (when both bit `1` and bit `2` are set) keeps horizontal bias and left/right margins + gone margins physical without RTL mirroring; `Flow` helpers similarly honor `parse_constraint_phys_flags` on their own outer horizontal constraints in RTL.
   - On the vertical axis, the low (top) edge resolves from `RULE_CONSTRAINT_TOP_TO_TOP` or `RULE_CONSTRAINT_TOP_TO_BOTTOM` plus top margin, and the high (bottom) edge resolves from `RULE_CONSTRAINT_BOTTOM_TO_BOTTOM` or `RULE_CONSTRAINT_BOTTOM_TO_TOP` minus bottom margin.
6. **Sizing (`0dp`, default size `294`, ratio `219`, percent `220..=221`, size bounds `280`, fixed/wrap/match):**
   - `Visibility::Gone` children resolve to size `0.0`.
   - `Size::Dp(v)` with `v <= 0.0` (`0dp` match-constraint) checks in order: (a) matching `DimensionRatio` (`other * ratio` for width, `other / ratio` for height), (b) `RULE_CONSTRAINT_DEFAULT_SIZE = 294`: when `"percent"`, multiplies `RULE_CONSTRAINT_WIDTH_PERCENT` / `RULE_CONSTRAINT_HEIGHT_PERCENT` (`220`/`221`) by the parent's inner extent even with dual anchors; when `"wrap"`, measures intrinsic `Size::Wrap` (using active `TextMetrics`) clamped to `<= available_span` so constrained text wraps onto multiple lines; when `"spread"` (default), applies percent if set (returning `0.0` if wrapping and not dual-anchored) or dual-anchored `(high - low).max(0.0)`, else `0.0`. In all modes, the resulting size clamps through `apply_constraint_size_bounds` using density-scaled `RULE_CONSTRAINT_SIZE_BOUNDS = 280` min/max dp limits and positions via RTL-aware horizontal/vertical bias (`204`/`205`).
   - `Size::Dp(v)` with `v > 0.0` scales to `state.dp(v)`.
   - `Size::Wrap` measures intrinsic width or height using active `TextMetrics` (or copies the bound target's size on a `Placeholder` carrying `RULE_CONSTRAINT_PLACEHOLDER = 282`); when `RULE_CONSTRAINT_SIZE_BOUNDS = 280` marks `constrained_w`/`constrained_h` on a dual-anchored child, clamps to `(high - low).max(0.0)` and applies density-scaled min/max limits so constrained text wraps onto multiple lines.
   - `Size::Match` fills the available constrained span, or falls back to intrinsic measurement when the `ConstraintLayout` parent itself is wrapping on that axis.
7. **Placement, baseline alignment (`222` & `223` `goneMarginBaseline`), RTL wrap-content width, and cycle safety:**
   - On the vertical axis, `RULE_CONSTRAINT_BASELINE_TO_BASELINE` resolves the target sibling's baseline (`target_pos + relative_baseline(...)`) and places the child at `target_baseline - own_baseline` when both views report a baseline (applying density-scaled `goneMarginBaseline` from `RULE_CONSTRAINT_GONE_MARGINS = 223` via `parse_gone_margins_full` when the referenced baseline anchor has effective visibility `Visibility::Gone`, or falling back to top/bottom edge constraints when no baseline is reported).
   - Dual-constrained children without baseline alignment are positioned at `low + ((high - low) - size) * bias`; single-edge children align flush to their constrained edge; unconstrained children anchor to the container's start edge (physical right in RTL horizontal layout, otherwise physical left/top) plus margin.
   - When the parent is wrapping horizontally, `resolve_edge_info("parent", ...)` defers the logical end edge (`!target_high` in RTL, `target_high` in LTR) rather than always deferring physical right, and `layout_intrinsic`/`intrinsic` measure wrap width from the container's right edge `(inner.x + inner.width) - (r.x - m[0])` in RTL (ignoring `Gone` children and helpers). Recursive sibling/barrier lookups are memoized with a `visiting` guard so cyclic graphs terminate safely at the container origin with `0.0` size.
8. **`Flow` virtual layout (`232` & `292`), circular positioning (`233`), `Placeholder` (`282`), `Layer` (`281`), and dependent re-solve:**
   - `resolve_constraint_placeholders` maps `RULE_CONSTRAINT_PLACEHOLDER = 282` helpers to their active target sibling (`LayoutState::placeholder_content` override or static `content_id`); bound targets render and receive clicks/semantics solely in their Placeholder slot while empty Placeholders follow `emptyVisibility` (`gone`, `invisible`, `visible`).
   - After the primary horizontal/vertical (and optional width-ratio) passes, `constraint_layout_positions` runs `resolve_flow_helpers` when any child carries `RULE_FLOW = 232`: each `Flow` resolves its own box constraints/bias/percent/explicit dimensions, collects visible non-helper referenced siblings (skipping `Visibility::Gone` and `Group`-hidden views), arranges them across rows (`orient = 0`/`h`) or columns (`orient = 1`/`v`) using `FlowWrapMode::{None, Chain, Aligned}` with density-scaled `h_gap`/`v_gap`, `distribute_flow_line` (`spread`/`spread_inside`/`packed` + RTL-aware `h_bias`/`v_bias`, applying Wave 20A `parse_flow_ext_spec` `RULE_CONSTRAINT_FLOW_EXT = 292` `first_*` overrides to line `0` including single-line `Flow` and `last_*` overrides to line `len - 1` across horizontal/vertical `Flow`), cross-axis alignment (`flow_cross_offset` / `row_vertical_metrics` supporting `start`, `center`, `end`, `baseline`), and `max_wrap` in LTR or RTL, and records preset `(x, w)` and `(y, h)` intervals for both the `Flow` bounding box and every placed member.
   - Next, `resolve_circle_constraints` evaluates `RULE_CONSTRAINT_CIRCLE = 233` via memoized cycle-guarded recursion (`visiting`), resolving `"parent"` or sibling centers (supporting chained circular targets), computing `cx = tcx + state.dp(radius_dp) * angle_rad.sin()` and `cy = tcy - state.dp(radius_dp) * angle_rad.cos()` (`0°` = 12 o'clock clockwise), and recording preset positions.
   - If either `Flow` or circular positioning updated any preset intervals, `constraint_layout_positions` re-runs horizontal and vertical `constraint_layout_axis` passes seeded with `preset_x`/`preset_y` so siblings constrained to a `Flow` bounding box or circularly positioned view settle to exact final coordinates.
   - During rendering, `RULE_CONSTRAINT_LAYER = 281` groups compute the union `Rect` of visible referenced siblings, expand `bg_rect` by Layer padding, and render Layer elevation + background + referenced members together inside balanced `PushTransform` (around union center) and `PushLayer` (`view_alpha * state.view_alpha`) passes.

## Motion and animation

`ConstraintLayout` applies placement directly with no intrinsic layout animation clock; child controls supply their own state layers and effects. See the [Static motion profile](../motion.md#motion-profiles). Animated `ConstraintSet` transitions and `MotionLayout` are not implemented.

**Reduced motion:** Placement remains direct; child controls follow the shared reduced-motion preference.

## Performance and lifecycle

Axis placement runs over direct children in linear memoized passes during frame layout (at most one extra horizontal+vertical refresh when a child uses width-targeted `DimensionRatio`) with no persistent timers or idle redraw loop. Transient child widget state remains keyed by stable view IDs and cleaned up by Bhoo's standard lifecycle rules.

## Acceptance criteria

- Resolve parent and sibling edge anchors (`196..=203`) with padding and physical/relative margins in both LTR and RTL, including RTL wrap-content width measurement.
- Center dual-anchored children by default (`0.5` bias) and honor explicit horizontal/vertical bias (`204..=205`), mirroring horizontal bias in RTL.
- Size `0dp` match-constraint children between opposing anchors on both axes and compute `wrap_content` vertical heights using constrained widths.
- Position vertical and horizontal `Guideline` helpers (`210..=213`) end-to-end (importer + runtime) by `begin`, `end`, and `percent` in LTR and RTL without emitting semantic nodes or inflating wrap bounds.
- Solve horizontal and vertical bidirectional chains (`214..=217`) end-to-end (importer + runtime) for `spread`, `spread_inside`, `packed`, weighted `0dp` chains, and `Gone` chain members.
- Solve `DimensionRatio` (`219`), `Width`/`Height_percent` (`220..=221`), `Baseline_toBaselineOf` (`222`), `goneMargin*` including 7-value `layout_goneMarginBaseline` (`223`), enhanced dynamic `Barrier` with `barrierMargin` / `barrierAllowsGoneWidgets` (`224`), `Group` visibility propagation (`225`), extended `Flow` virtual layout (`232`) with per-first/last-line chain style & bias overrides (`292`), circular positioning (`233`), constrained wrap & min/max size bounds (`280`), `Layer` (`281`), `Placeholder` (`282`), physical vs. logical horizontal pinning (`287`), and `layout_constraintWidth_default`/`Height_default` (`294`) end-to-end (importer + runtime) in LTR and RTL.
- Reject invalid ConstraintLayout anchors, invalid ratios/biases/percents/default-size modes, unsupported chain styles, invalid negative weights, invalid Barrier directions/`barrierMargin`/`barrierAllowsGoneWidgets`, invalid Flow orientations/wrap modes/styles/biases/alignments/`flow_maxElementsWrap`, invalid `Placeholder` content/`emptyVisibility`, invalid constrained-wrap booleans or negative min/max dimensions, invalid circular targets/angles, and unsupported `app:layout_constraint*` attributes during XML compilation.
- Implement remaining AndroidX ConstraintLayout features (`ConstraintSet` and `MotionLayout`), and verify measurements against Android on a real device.

## Remaining limitations

- **Other helpers and virtual layouts:** Custom `ConstraintHelper` subclasses remain unimplemented at runtime.
- **Physical bias/margin flag emission:** The runtime solver supports `RULE_CONSTRAINT_PHYS_FLAGS = 287` bit `4` (keeping horizontal bias and left/right margins physical when both anchors are physical), while `tools/import-android-layout.py` currently emits bits `1` and `2` (`"1"`, `"2"`, `"3"`) for physical anchor edges (preserving RTL horizontal bias mirroring when `layout_constraintHorizontal_bias` is used).
- **Cycle reporting:** Cyclic sibling constraints are broken safely at runtime instead of failing XML compilation with a dedicated compile-time cycle check.
- **Dynamic sets and motion:** `ConstraintSet` mutation/cloning and `MotionLayout` keyframes/transitions are not implemented.
- **Platform parity:** AndroidX Cassowary/linear-solver edge cases, nested wrap-content combinations, Android font/theme metrics, and real-device visual parity remain unverified.
