## Scope and variants

Android XML `<Button>`, `<androidx.appcompat.widget.AppCompatButton>`, and `<com.google.android.material.button.MaterialButton>` (plus `<ExtendedFloatingActionButton>` and `<Chip>` aliases in `tools/import-android-layout.py`, with `Chip` emitting `RULE_CHIP_STYLE = 230` — see [Android XML support](../android-xml.md) and [Chip](chip.md)) compile to `bhoo::android_xml::Kind::Button` with text labels, enabled/disabled states, explicit XML sizing/padding/backgrounds, built-in `Widget.Material3.Button*` / `Widget.MaterialComponents.Button*` / `Widget.AppCompat.Button.Borderless*` style presets, `RULE_BUTTON_VARIANT = 229` MaterialButton variants, and runtime `LayoutState.theme_style: AndroidTheme` default chrome.

## State and interaction contract

Enabled buttons emit their view ID when activated; disabled buttons do not. The host can change the displayed label with `LayoutState.text`, keyed by view ID. Text size, bold, all-caps, letter spacing, supported text color selectors, RTL-aware `android:textAlignment` (`RULE_TEXT_ALIGNMENT = 195`), and gravity apply to the label.

### `AndroidTheme` default button parity

When a `Kind::Button` omits an explicit `background`, `background_stroke`, background state selector (`kind: 96`), `RULE_DRAWABLE_LAYER` (`208`), or `RULE_GRADIENT` (`207`), `codes/libs/ui/libbhoo/src/systems/android/xml/mod.rs` renders default theme chrome controlled by `LayoutState.theme_style: AndroidTheme` (see [Android XML support](../android-xml.md)):

| `MaterialLight` | AOSP `Widget.Material.Light.Button` (`Theme.Material.Light`) | Inset `4dp` horizontally (`button_inset_horizontal_material`) and `6dp` vertically (`button_inset_vertical_material` -> `36dp` visual height on a `48dp` button via `default_button_visual_bounds`), `2dp` corner radius | `#D6D7D7` fill (`RULE_BACKGROUND_TINT` overrides; `0.38` alpha when disabled) + subtle 2dp resting shadow (`paint_material_button_shadow`, two density-scaled ambient/key `DrawCommand::Shadow` layers fitting inside the `4dp` horizontal inset) when enabled (explicit `RULE_ELEVATION` overrides via unscaled-dp `elevation_level_from_dp`) | `14sp` medium (`weight: 500`, centered), `1.34×` Android Roboto line height (`text_line_height_factor`), `#DE000000` (`0.38` alpha when disabled), uppercase by default (e.g. `CONTINUE`) | `88dp` min width; `[12, 10, 12, 10]` dp default padding (`4dp H / 6dp V` inset + `8dp H / 4dp V` AOSP button padding) | `#000000` ripple clipped to inset `2dp`-radius bounds |

- **`RULE_TEXT_ALL_CAPS = 218`:** `tools/import-android-layout.py` emits `RelativeRule { kind: RULE_TEXT_ALL_CAPS (218), anchor: "true" | "false" }` whenever `android:textAllCaps` is set directly, via `@style`, via `textAppearance`, or via `@bool`. At runtime, `effective_text_all_caps` checks `RULE_TEXT_ALL_CAPS` first; buttons carrying `RULE_BUTTON_VARIANT = 229` or `RULE_CHIP_STYLE = 230` preserve sentence case unless `text_all_caps` is enabled, and plain buttons under `MaterialLight`/`MaterialDark` default to uppercase unless explicitly opted out.
- **`RULE_RIPPLE_COLOR = 209`:** `tools/import-android-layout.py` emits `RULE_RIPPLE_COLOR = 209` (`"r,g,b,a"` or `"r,g,b,a|unbounded"`) from XML `<ripple>` drawables (on `android:background` or `android:foreground`) and `app:rippleColor` on `Button`/`MaterialButton`. At runtime `paint_state_layer` overrides the button's default ripple tint, suppresses hover/press ripples completely when resolved alpha is `0` (`#00000000`), and supports unbounded circular ripples when requested.
- **Centered single-line overhang slack:** When rendering a simple single-line centered button label (`align == 1`) with no compound drawables, `Kind::Button` expands its horizontal text draw rect by `slack = padding[0].min(padding[2]).min(state.dp(6.0))` on each side so edge glyph overhangs do not clip against horizontal padding.
- **Wrap-content uppercase measurement:** Horizontal and vertical wrap-content measurement (`layout_intrinsic`) uses `effective_text_all_caps`, `effective_text_font` (`14sp` medium unless an explicit non-default `textSize` or `bold` is set), `text_line_height_factor` (`1.34×` under `MaterialLight`/`MaterialDark`/`Material3Light`/`Material3Dark`; `1.5×` under `Bhoo`), `default_theme_padding` (`[12, 10, 12, 10]` dp under `MaterialLight`/`MaterialDark`, `[24, 10, 24, 10]` dp under `Material3Light`/`Material3Dark` and non-text `RULE_BUTTON_VARIANT`, `[12, 10, 12, 10]` dp under `text` variant), and `default_button_min_width` (`88dp` Material, `64dp` Material 3 / non-text `RULE_BUTTON_VARIANT`, `48dp` `text` variant / `Chip` / Bhoo), plus any explicit XML padding, compound drawables, or supported drawable minimum size. Linear, frame, and relative/constraint containers use this measured width so uppercase `MaterialLight`/`MaterialDark` buttons do not truncate or under-measure.

### `MaterialButton` variants (`RULE_BUTTON_VARIANT = 229`) and `app:` attributes (Wave 4A & 4B)

`tools/import-android-layout.py` (`detect_button_variant`) detects Material button variants from the tag (`MaterialButton` defaults to `filled`) and resolved style inheritance chains (including local `@style/` parents, `?attr/materialButtonOutlinedStyle`, `Widget.Material3.Button.TonalButton`, `TextButton`, `Borderless` / `?attr/borderlessButtonStyle`, `ElevatedButton`, and `?attr/materialButtonElevatedStyle`), emitting `RelativeRule { kind: RULE_BUTTON_VARIANT (229), anchor: "<variant>" }`. Plain `<Button>` and `<AppCompatButton>` elements without a variant style emit no rule `229` and retain `AndroidTheme` default button chrome.

At runtime in `codes/libs/ui/libbhoo/src/systems/android/xml/mod.rs`, `active_button_variant()` activates whenever `RULE_BUTTON_VARIANT = 229` is present and the node has neither `RULE_CHIP_STYLE = 230` nor an explicit custom background (`background`, state selector `kind: 96`, `RULE_DRAWABLE_LAYER = 208`, `RULE_STATEFUL_DRAWABLE_LAYER = 231`, or `RULE_GRADIENT = 207`). Active variants inset `4dp` vertically (`default_button_visual_bounds`), default to a full-pill radius (`visual_b.height * 0.5`) unless explicit `radius` or `RULE_CORNER_RADII` is provided, and render `14sp` medium sentence-case text:

| `RULE_BUTTON_VARIANT` | Default fill & elevation | Default border (`background_stroke`) | Label & state-layer color | Default min width & padding |
| --- | --- | --- | --- | --- |
| `filled` | `t.primary` (`RULE_BACKGROUND_TINT` overrides; `0.38` alpha disabled); no default shadow | None (honors explicit `app:strokeColor`/`strokeWidth` if set) | `t.on_primary` (`0.38` alpha disabled) | `64dp`; `[24, 10, 24, 10]` dp |
| `outlined` | Transparent (honors non-transparent `RULE_BACKGROUND_TINT`); no default shadow | `1dp` `t.outline` (`t.text` at `0.12` alpha disabled), or explicit `background_stroke`/`background_stroke_width` painted once on `visual_b` | `t.primary` (`0.38` alpha disabled) | `64dp`; `[24, 10, 24, 10]` dp |
| `tonal` | `t.secondary_container` (`RULE_BACKGROUND_TINT` overrides; `0.38` alpha disabled); no default shadow | None (honors explicit stroke if set) | `t.on_secondary_container` (`0.38` alpha disabled) | `64dp`; `[24, 10, 24, 10]` dp |
| `text` | Transparent (honors non-transparent `RULE_BACKGROUND_TINT`); no shadow | None (honors explicit stroke if set) | `t.primary` (`0.38` alpha disabled) | `48dp`; `[12, 10, 12, 10]` dp |
| `elevated` | `t.surface_low` (`RULE_BACKGROUND_TINT` overrides; `0.38` alpha disabled) + level-1 `DrawCommand::Shadow` (blur `3.0` at 1x density) when enabled | None (honors explicit stroke if set) | `t.primary` (`0.38` alpha disabled) | `64dp`; `[24, 10, 24, 10]` dp |

**`MaterialButton` XML attributes (`APP_BUTTON_ATTRS` in `tools/import-android-layout.py`):**

- `app:icon`: maps to compound `drawableStart` (when `android:drawableStart` is unset), preserving `@null` to emit a zero-size clear rule (`kind: 173`), rasterizing referenced `<vector>` / PNG assets into `install_drawables(state)`, and emitting `RULE_COMPOUND_ANIMATION_LIST = 295` (`"start:..."`, Wave 21A/21B) when `app:icon` resolves to an `<animation-list>` (including `<inset>`-wrapped lists).
- `app:iconTint`: maps to `drawableTint` (`kind: 176`), ignoring `@null`.
- `app:iconPadding`: maps to `drawablePadding` (`kind: 175`).
- `app:iconGravity`: validated against `start`, `textStart`, `end`, `textEnd`, `top`, and `textTop` (rejecting unsupported values with `ValueError`).
- `app:iconSize`: validated as an Android dimension.
- `app:cornerRadius`: populates `Node.radius` when not set by an explicit shape background (overrides `app:shapeAppearance` / `app:shapeAppearanceOverlay`).
- `app:shapeAppearance` and `app:shapeAppearanceOverlay` (Wave 5A & Wave 17A/17B): resolve pinned `material-android` and local `<style>` `cornerSize*` (`dp`/`sp`/`px`/`%`, with uniform `>= 50%` emitting full-pill `radius: -1.0` and asymmetric corners emitting `RULE_CORNER_RADII = 206`) and `cornerFamily*` (`rounded`/`0`, `cut`/`1`, `?attr/shapeCornerFamily`, emitting `RULE_CORNER_FAMILY = 278` `"<tl>,<tr>,<br>,<bl>"` when any corner is `cut`), both directly and when inherited through a button's `@style/`. At runtime, `Kind::Button` renders chamfered/mixed cut fills via bounded cached `Image`s (`LayoutState::cut_shape_images`, `256×256` / 48 entries / 4 MB) and miter-inset outlines via `DrawCommand::Line`/`Arc`.
- `app:strokeColor` and `app:strokeWidth`: populate `Node.background_stroke` (ignoring `@null`) and `Node.background_stroke_width` when not set by an explicit shape background.
- `app:rippleColor`: emits `RULE_RIPPLE_COLOR = 209` when no explicit `<ripple>` drawable is present.

XML backgrounds accept solid shapes (rectangle, oval, `line`, `ring`), per-corner `<corners>` (`RULE_CORNER_RADII = 206`), chamfered `cut` corners (`RULE_CORNER_FAMILY = 278`), linear, radial, and sweep `<gradient>` drawables (`RULE_GRADIENT = 207`), `<layer-list>` / `<inset>` (`RULE_DRAWABLE_LAYER = 208`), `<ripple>` (`RULE_RIPPLE_COLOR = 209`, suppressing `#00000000`), wrapper drawables (`<rotate>`, `<scale>`, `<clip>`, `<level-list>`, `<transition>`), `<bitmap>`, uniform color `<selector>` (`kind: 96`), stateful shape/layer `<selector>` (`RULE_STATEFUL_DRAWABLE_LAYER = 231`), and `.9.png` guide-border decoding with single- and multi-segment UV stretch slicing (`RULE_BACKGROUND_IMAGE = 251`, `RULE_STATEFUL_BG_IMAGE = 254`). Full Android text shaping, locale-specific case conversion, animated state-list drawables, and all container measurements remain incomplete.

## Motion and animation

Bhoo's shared state-layer and radial ink ripple engine supplies hover and press feedback ([Feedback motion profile](../motion.md#motion-profiles)), honoring `RULE_RIPPLE_COLOR = 209` and clipping ripples to the button's resolved visual bounds and corner radius (including inset `2dp` bounds under `MaterialLight`/`MaterialDark`, pill/custom-radius bounds under `Material3Light`/`Material3Dark` and `RULE_BUTTON_VARIANT = 229`, and nested wrap-content containers). Timed `<animation-list>` compound and `app:icon` drawables (`RULE_COMPOUND_ANIMATION_LIST = 295`, Wave 21A/21B, including on Extended FAB) advance frames via `f.time()` and clip-gated `f.wake_at()` wakeups (looping or `oneshot`-clamping). AOSP/Material `stateListAnimator` press-elevation transitions (`button_state_list_anim_material` / `m3_btn_state_list_anim`) and Android device motion parity remain open.

**Reduced motion:** State-layer and ripple transitions follow the shared reduced-motion preference in `bhoo`; timed `<animation-list>` compound/icon drawables freeze strictly on frame `0` with zero wakeup.

## Acceptance criteria

- Check short, long, and multi-line labels, runtime text updates, padding, activation, and disabled state (`0.38` alpha, no elevation shadow under `MaterialLight`/`MaterialDark` or `elevated` variant).
- Check start/end gravity and `android:textAlignment` in both LTR and RTL.
- Verify `AndroidTheme` defaults (`MaterialLight`, `MaterialDark`, `Material3Light`, `Material3Dark`, `Bhoo`), `RULE_BUTTON_VARIANT = 229` (`filled`, `outlined`, `tonal`, `text`, `elevated`) and custom background override, `MaterialButton` `app:icon*`/`cornerRadius`/`stroke*` attributes, `RULE_TEXT_ALL_CAPS = 218` opt-out, `RULE_RIPPLE_COLOR = 209`, timed `<animation-list>` compound/icon drawables (`RULE_COMPOUND_ANIMATION_LIST = 295`), uniform auto-sizing / extended line layout (`RULE_TEXT_LAYOUT_EXT = 296`), and wrap-content uppercase width measurement.
- Compare theme appearance, layout, and motion side-by-side against Android (Waydroid) with matched theme, viewport, density, and font scale.

## Compound drawables

`drawableLeft`, `drawableRight`, `drawableStart`, `drawableEnd`, `drawableTop`, `drawableBottom`, `app:drawable*Compat`, `MaterialButton` `app:icon`, and `drawablePadding` accept solid rectangle/rounded-rectangle/oval shapes, supported shape selectors, timed `<animation-list>` multi-frame sequences (`RULE_COMPOUND_ANIMATION_LIST = 295`, Wave 21A/21B, including `<inset>`-wrapped lists and `autoMirrored` `255`), and `<vector>` XML references (rasterized into `install_drawables` and currently represented in static compound-drawable layout by their intrinsic dimensions and resolved tint/fill color). `drawableTint` and `drawableTintMode` support the existing local selector and six blend-mode subset. Logical start/end mirror in RTL; the wrap-content width reserves the drawable bounds and gap. Drawable selectors can respond to pressed, enabled, focused, selected, activated and hovered states. Wrap-content height reserves top/bottom drawable heights and gaps, horizontal drawable height, text line height and vertical padding, with the theme's minimum height (`48dp`). The initial multi-line measurement uses Bhoo line wrapping and does not reproduce complete Android font metrics. Full static rasterized vector/bitmap compound drawable rendering, `<animated-vector>`/`<animated-selector>` compound drawables, complete tint compositing, and device visual parity remain unverified.

## Multi-line labels

Buttons wrap supported text to the available width and measure wrap-content height from the displayed lines, line spacing, drawable extents and padding, including Wave 21A/21B `RULE_TEXT_LAYOUT_EXT = 296` uniform auto-sizing (`autoSizeTextType="uniform"` binary-searched step-quantized sizing), DP `balanced`/`high_quality` line breaking, soft hyphenation splitting oversized words with `'-'`, and RTL-aware `inter_word` justification. The renderer honors the supported single-line, line-limit and end-ellipsis subset. Bhoo centers the text block by default and honors supported explicit vertical gravity; its Unicode line breaking and typography do not establish Android TextView parity. Bhoo reports the first rendered line’s baseline for alignment, including supported top drawable space and vertical gravity. Android baseline/font parity and complex shaping remain open.

## Single-line ellipsis

For `maxLines="1"` with `ellipsize="start"`, `"middle"`, `"end"`, or `"marquee"`, Button uses the corresponding single-line truncation (`marquee` compiles to single-line end-ellipsized text) even when `singleLine` is not set. Bhoo applies its existing Unicode-aware ellipsis routine and retains the original Button action and label identity. Animated marquee scrolling, multi-line start/middle ellipsis, complex shaping, Android font metrics, and device parity remain unverified.

## Remaining limitations

- **`MaterialButton` icon layout & toggle controls:** `app:iconGravity` (`start`/`textStart`/`end`/`textEnd`/`top`/`textTop`) and `app:iconSize` are validated at import time, while runtime icon placement currently routes `app:icon` through leading `drawableStart` compound-drawable positioning (without distinct `textStart`/`end`/`top` gravity placement or custom `iconSize` scaling). Checkable `MaterialButton` / `MaterialButtonToggleGroup` segmented toggle styling remains open.
- **State-list elevation animators:** Pressed/hovered elevation transitions (`stateListAnimator`) are not implemented; `MaterialLight`/`MaterialDark` buttons use static 2-layer subtle 2dp resting shadows (`paint_material_button_shadow`) and `elevated` buttons use static level-1 shadows when enabled.
- **Typography and locale casing:** `to_uppercase()` does not implement locale-specific Android case mappings, `autoSizePresetSizes` / `justificationMode="inter_character"` / dictionary hyphenation patterns remain open, and Bhoo's `fontdue` font metrics/shaping still leave a `~1–2px` font-ascent/subpixel rasterization delta compared to Android Roboto/FreeType + HarfBuzz.
- **Drawables and device parity:** `<animated-vector>` and compound-slot `<animated-selector>` drawables, full static rasterized compound/background vector drawables, and multi-variant (`Material3Light`/`Material3Dark`, `RULE_BUTTON_VARIANT`, icons, pressed/disabled states) plus interactive/motion Waydroid comparisons beyond the single-screen `MaterialLight` static baseline remain open.
