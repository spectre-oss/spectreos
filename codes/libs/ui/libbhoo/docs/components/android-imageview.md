# Android XML ImageView

Status: Partial XML support for host-supplied and bundled PNG/9-patch/vector images, scale modes, Wave 14A/17A/17B multi-segment `.9.png` slicing (`251..=254`) and RTL `autoMirrored` (`255`), Wave 18A/18B timed `<animation-list>` playback (`285`), Wave 19A/19B dynamic wrapper drawables (`286`), Wave 20A/20B `<animated-selector>` transitions (`293`), and Wave 24A/24B sampled `<animated-vector>` keyframe playback (`RULE_ANIMATED_VECTOR = 309`); SVG `pathData` morphing, `Animatable2` callbacks, and Android device visual parity remain open.

| Field | Decision |
| --- | --- |
| Category | Android XML views |
| Kind | Android framework widget |
| Priority | P1 |

## Scope and variants

Android ImageView with a drawable resource name, fit-center, center-crop, fit-XY, center, center-inside, fit-start or fit-end scaling, optional background and initial `adjustViewBounds` measurement.

## State and interaction contract

The XML importer can bundle unqualified non-interlaced 8/16-bit RGB/RGBA and grayscale PNGs, plus indexed PNG drawables at build time. Hosts can also supply decoded images by name through layout state. ImageViews update wrap-content dimensions when their drawable is replaced, including anonymous children in nested layouts. `adjustViewBounds` preserves the drawable aspect ratio for wrap-content height with fixed, match-parent or width-constrained width, and for wrap-content width with fixed height. Padding is excluded from the aspect calculation; replaced images remeasure. `maxWidth` and `maxHeight` limit the supported wrap-content dimensions when adjustment is enabled. Other height-constrained cases and exact framework measurement remain incomplete. Missing images draw no content. `android:imageAlpha` changes drawable opacity without changing the view background. Literal and `@color` image tints support the Android ImageView XML default `src_atop` and the explicit `src_in`, `src_over`, `multiply`, `screen` and `add` modes; alpha is composited into a bounded per-layout cache without changing the background. `res/color` selectors support ordered enabled, pressed, focused, selected, activated, hovered and checked conditions, negative state tests and item alpha; selected and activated values are host-controlled, while checked is present only on checkable widgets. Theme attributes, other selector states and animated color transitions remain unsupported. Density and AOSP resource qualifiers (`--locale`, `--ldrtl`/`--ldltr`, `--night`, `--orientation`, `--sw`, `w<N>dp`, `v<N>`) are resolved at build time; live runtime qualifier switching, other image formats, arbitrary affine transforms, `<animated-vector>` SVG `pathData` morphing, `<animated-vector>` / `<animated-selector>` playback outside `src`/`background`, and full drawable parity remain incomplete.

`android:scaleType="matrix"` uses an identity transform by default. Hosts may supply `[scale_x, scale_y, translate_x, translate_y]` via `LayoutState.image_matrices` keyed by view ID; negative scales reflect the image, and zero or non-finite scales draw no image. Transform coordinates are logical pixels relative to the padded content origin. Browser packet rendering is tested for horizontal, vertical and two-axis reflection using a four-color image; native horizontal reflection is also checked by framebuffer pixels under headless Weston and Mesa GLES at 1× and 2× scale. Rotation, skew, perspective and Android device comparisons are not yet supported.

`android:baseline` specifies an image baseline from the view top, while `android:baselineAlignBottom="true"` uses its measured bottom and overrides the explicit baseline. Shared baseline-aware LinearLayout, TableRow, GridLayout and RelativeLayout measurement can use these values. Without either setting, ImageView reports no baseline. Exact Android font metrics and device comparison remain open.

`android:cropToPadding` controls clipping of oversized `center` and `centerCrop` images. With the default false, the image may extend into the padded area while remaining inside the view bounds; with true, it is clipped to the padded content area. Android cases involving ancestor clipping and exact subpixel geometry remain unverified.

In Wave 14A and Wave 17A/17B, `Kind::Image` supports single- and multi-segment `.9.png` UV stretch slicing (`decode_nine_patch_bands` in [`tools/android_png.py`](../../../../tools/android_png.py) -> `RULE_IMAGE_NINE_PATCH = 252`, `RULE_BACKGROUND_IMAGE = 251`, splitting each axis into alternating density-scaled fixed segments and stretchable segments distributing remaining pixels proportionally across all stretch bands via `nine_patch_axis_segments`), live 7-bit stateful `src` `<selector>` switching (`RULE_STATEFUL_IMAGE_SRC = 253`), and RTL-only horizontal mirroring for `android:autoMirrored="true"` (`RULE_AUTO_MIRRORED = 255` via `PushTransform`/`PopTransform`), verified by `wave14a_image_nine_patch_and_stateful_src_on_image_and_icon`, `wave14a_auto_mirrored_flips_image_icon_and_toolbar_nav_in_rtl_only`, and `wave17a_multi_segment_nine_patch_stretch_bands` in [`tests/android_xml.rs`](../../tests/android_xml.rs) plus `test_wave17b_multi_band_nine_patch` in [`tools/test-android-layout.py`](../../../../tools/test-android-layout.py).

In Wave 18A and Wave 18B, `Kind::Image` (and view backgrounds) also supports timed `<animation-list>` frame playback (`RULE_ANIMATION_LIST = 285`, `"<oneshot:0|1>|<img_key_0>:<dur_ms_0>,..."`): `tools/import-android-layout.py` decodes/rasterizes all frames (PNG, `.9.png`, `<vector>`, inline `<shape>`, propagated through `<inset>` wrappers, with cycle rejection and frame-0 static fallback) into `install_drawables`, while `codes/libs/ui/libbhoo/src/systems/android/xml/mod.rs` selects the active frame from `f.time()`, schedules exact next-frame wakeups via `f.wake_at(...)` only while visible inside the clip rect, wraps modulo total duration when `oneshot = 0`, stops and clamps on the final frame with no wakeup when `oneshot = 1`, honors `LayoutState.image_sources` host overrides, and freezes strictly on frame `0` with no wakeup under `MotionPreference::Reduced`.

In Wave 19A and Wave 19B, `Kind::Image` (and view backgrounds) adds dynamic wrapper drawables (`RULE_DRAWABLE_DYNAMIC = 286`): `decode_dynamic_drawable` in [`tools/import-android-layout.py`](../../../../tools/import-android-layout.py) bundles child drawables into `images` and emits `src:` (`android:src` / `app:srcCompat`) and `bg:` (`android:background`, propagating through `<inset>`, `<ripple>`, and single-item `<layer-list>`) rules for `<level-list>` (`level|<min0>:<max0>:<key0>,...`), `<clip>` (`clip|<h|v>|<gravity>|<key>`), `<rotate>` (`rotate|<from_deg>,<to_deg>|<px>,<py>|<key>`), `<scale>` (`scale|<sw>,<sh>|<gravity>|<key>`), and `<transition>` (`transition|250|<key0>,<key1>`), preserving static fallback fields. At runtime in [`codes/libs/ui/libbhoo/src/systems/android/xml/mod.rs`](../../src/systems/android/xml/mod.rs), `LayoutState::drawable_level: HashMap<String, u32>` (`0..=10000`, defaulting to `0`) drives `level` selection, RTL-aware `clip` bounds, pivoted `rotate` (`PushTransform`/`PopTransform`), and gravity-pivoted `scale` (`PushTransform`/`PopTransform`), while `LayoutState::drawable_transition_active: HashMap<String, bool>` (backed by internal timed `DrawableTransitionMotion`) drives `PushLayer`/`PopLayer` `transition` crossfades for both `bg:` and `src:`.

In Wave 20A and Wave 20B, `Kind::Image` (and view backgrounds) adds `<animated-selector>` transition frame playback (`RULE_ANIMATED_SELECTOR = 293`): `decode_animated_selector_transitions` in [`tools/import-android-layout.py`](../../../../tools/import-android-layout.py) parses `<item android:id>` 7-bit state masks and `<transition android:fromId android:toId android:reversible>` `<animation-list>` frames across `src`/`srcCompat` (`ctx="src"`) and `background` (`ctx="bg"`, propagating through `<inset>`/`<ripple>`/`<layer-list>`), bundling frames and emitting `"<ctx>:<from_mask>:<to_mask>:<rev:0|1>|<img_key_0>:<dur_ms_0>,..."` while preserving existing `96`/`231`/`253`/`254` state items. At runtime in [`codes/libs/ui/libbhoo/src/systems/android/xml/mod.rs`](../../src/systems/android/xml/mod.rs), a bounded `animated_selector_states` map (capped at `256` entries) tracks the previous 7-bit `live_state_mask`, plays forward/reverse frame sequences via `f.time()`/`f.wake_at(...)` for both `src` (RTL `autoMirrored`-aware) and `bg`, settles onto the destination stateful drawable on completion, and cuts directly to the destination with zero wakeups under `MotionPreference::Reduced`.

In Wave 24A and Wave 24B, `Kind::Image`, `Kind::QuickContactBadge`, `Kind::Icon`, `Kind::Zoom`, and view backgrounds add sampled `<animated-vector>` keyframe playback (`RULE_ANIMATED_VECTOR = 309`): `eval_avd_interpolator` and `decode_animated_vector_frames` in [`tools/import-android-layout.py`](../../../../tools/import-android-layout.py) add the `AAPT` namespace (`http://schemas.android.com/aapt`), support both `<animated-vector android:drawable="@drawable/...">` and inline `<aapt:attr name="android:drawable"><vector>`, parse `<target android:name="...">` driven by external `@animator/...` or inline `<aapt:attr name="android:animation">` `<objectAnimator>` / `<set android:ordering="together|sequentially">` across `rotation`, `scaleX`, `scaleY`, `translateX`, `translateY`, `trimPathStart`, `trimPathEnd`, `trimPathOffset`, `fillAlpha`, `strokeAlpha`, and `alpha` (rejecting unsupported properties such as `pathData`, non-`floatType` value types, incompatible targets, out-of-range values, and cycles), sample `8` evenly-spaced interpolated keyframes (`<base>__avd0..7`) + frame-0 static fallback rasterized via [`tools/android_vector.py`](../../../../tools/android_vector.py), propagate `android:autoMirrored` (`RULE_AUTO_MIRRORED = 255`) and vector tint/tintMode, and emit repeatable `RelativeRule { kind: 309, anchor: "<ctx:src|bg>:<repeat:0|1>:<dur_ms>|<img_key_0>,...,<img_key_7>" }` on `android:src`/`app:srcCompat` and `android:background` (including through `<inset>`, `<layer-list>`, and `<ripple>`). At runtime in [`codes/libs/ui/libbhoo/src/systems/android/xml/mod.rs`](../../src/systems/android/xml/mod.rs), `parse_animated_vector` and `select_animated_vector_frame` play repeatable `src` and `bg` rules independently across `dur_ms` using `f.time()` and clip-gated `f.wake_at(...)`, looping modulo `dur_ms` when `repeat == 1`, clamping on the final frame with `0` wakeups when `repeat == 0`, settling immediately on `len - 1` (`repeat == 0`) or `0` (`repeat == 1`) with `0` wakeups under `f.reduced_motion()`, and honoring `LayoutState.image_sources`, tint, scale, alpha, rounded/asymmetric clipping, and RTL `autoMirrored` (verified by `wave18a_animation_list_looping_oneshot_wake_at_background_and_reduced_motion`, `wave19a_dynamic_wrapper_drawables_level_clip_rotate_scale_and_bg_prefix`, `wave19a_dynamic_drawable_transition_crossfade_and_reduced_motion`, `wave20a_animated_selector_src_bg_reverse_rtl_and_reduced_motion`, `wave24a_animated_vector_src_repeat_oneshot_clip_gating_rtl_mirror_and_reduced_motion`, and `wave24a_animated_vector_bg_and_dual_src_bg_repeatable_rules` in [`tests/android_xml.rs`](../../tests/android_xml.rs) [`332` passing tests; `927` default / `933` all-features Rust tests across `76` suites] and `test_wave18b_animation_list_rule_285`, `test_wave19b_dynamic_wrapper_drawables_rule_286`, `test_wave20b_animated_selector_transitions_rule_293`, and `test_wave24b_animated_vector_rule_309` in [`tools/test-android-layout.py`](../../../../tools/test-android-layout.py) [`258` passing tests, plus `0` diffs across `167` existing layouts]). Honest remaining limits: SVG `pathData` morphing between arbitrary path topologies is not interpolated per-frame (numeric group/path transform, trim, and alpha properties are interpolated), `colorType` animators and `repeatMode="reverse"` ping-pong frames are not generated, and programmatic `AnimationDrawable`/`Animatable2` start/stop/reset/callback control, custom-duration `TransitionDrawable` host APIs, `RULE_DRAWABLE_DYNAMIC` / `RULE_ANIMATED_SELECTOR` / `RULE_ANIMATED_VECTOR` inside `foreground`/compound-drawable/button/tick/indicator contexts, and Android device visual parity remain open.

## Motion and animation

Static images do not animate; `<animation-list>` drawables (`RULE_ANIMATION_LIST = 285`) advance frames by `f.time()` using bounded `f.wake_at(...)` wakeups only when visible inside the active clip rect and stop scheduling once a `oneshot` sequence finishes; `<transition>` drawables (`RULE_DRAWABLE_DYNAMIC = 286`) crossfade smoothly over `dur_ms` (default `250ms`) via hardware-composited `PushLayer`/`PopLayer` passes when `LayoutState::drawable_transition_active` toggles and stop requesting frames once settled; `<animated-selector>` transitions (`RULE_ANIMATED_SELECTOR = 293`) play forward/reverse `<animation-list>` frame sequences via `f.time()`/`f.wake_at(...)` tracked in the bounded `animated_selector_states` map (capped at `256` entries) and settle onto the destination stateful drawable with no wakeups once finished; and `<animated-vector>` drawables (`RULE_ANIMATED_VECTOR = 309`) advance across their `8` pre-sampled keyframes over `dur_ms` using `f.time()` and clip-gated `f.wake_at(...)`, looping modulo `dur_ms` when `repeat == 1` and clamping on the final frame with `0` wakeups once complete when `repeat == 0` (see [motion.md](../motion.md#scheduling-and-lifecycle)). Caller-controlled state can replace the supplied image via `LayoutState.image_sources` or adjust `LayoutState::drawable_level` directly.

**Reduced motion:** Static rendering remains unchanged; `<animation-list>` drawables freeze on frame `0` with no wakeups, `<transition>` drawables snap immediately to layer `0` or layer `1` without intermediate crossfade frames, `<animated-selector>` transitions cut directly to the destination stateful drawable with zero wakeups, and `<animated-vector>` drawables settle directly on `len - 1` (`repeat == 0`) or frame `0` (`repeat == 1`) with zero wakeups.

## Acceptance criteria

- Import drawable resource IDs and supported scale modes.
- Verify fit-center geometry and center-crop source coordinates.
- Verify `<animated-vector>` (`RULE_ANIMATED_VECTOR = 309`) repeating/one-shot timing, offscreen clip wakeup suppression, dual `src`+`bg` playback, RTL `autoMirrored`, and reduced-motion settling.
- Compare sizing, scaling and clipping with Android on a device.
