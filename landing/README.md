# SpectreOS documentation & landing site

Static site for <https://spectre.foo/>, generated by a small
**pure Node.js** script (Node 20+, **zero npm dependencies**: no `npm install`, no lockfile).

Most pages are compiled straight from the documentation that lives next to the code
(`README.md`, `codes/**/README.md`, `docs/writing-spectreos-apps/*.md`, `SECURITY.md`), so the
site cannot drift from the repository. Authored pages live in `src/content/` and `scripts/lib/pages.mjs`.

## Commands

Run from this directory (`landing/`):

| Command | What it does |
| --- | --- |
| `npm run build` | Builds the site into `landing/dist/` with `BASE_PATH=/` (`https://spectre.foo/`). Takes well under a second. |
| `npm run preview` | Builds with `BASE_PATH=/` and serves `dist/` at <http://127.0.0.1:4173/> (`PORT`, `HOST` override). |
| `npm test` | Unit-tests the Markdown compiler, builds for `/`, `/spectreos/` and a custom base, and validates the output. |

Environment variables for `scripts/build.mjs`:

| Variable | Default | Purpose |
| --- | --- | --- |
| `BASE_PATH` | `/` | URL prefix of the deployed site (e.g. `/` for `spectre.foo`, `/spectreos/` for subpath hosting). Slashes are normalised. |
| `OUT_DIR` | `landing/dist` | Output directory. |
| `SITE_ORIGIN` | `https://spectre.foo` | Used for the sitemap and canonical URLs. |
| `REPO_BRANCH` | `main` | Branch used when rewriting repo links to GitHub blob/tree URLs. |
| `BUILD_SHA` | `git rev-parse` | Commit shown in the footer (`GITHUB_SHA` is honoured in CI). |

## CI usage

```sh
cd landing
npm run build          # -> landing/dist (upload this directory as the Pages artifact)
npm test               # validation; does not touch landing/dist
```

No dependency installation step is needed, only `actions/setup-node` with Node 20+ (or any runner
that already has `node`). The build reads files outside `landing/` (`README.md`, `docs/**`,
`codes/**/README.md`, `.version` / `VERSION` files), so use a full checkout; submodules are **not** needed.

## What gets generated

`dist/` contains `index.html`, `docs/**/index.html` (overview, getting started, libbhoo, Wisp, apps,
writing apps + 4 chapters, Spectre NixOS · Poco F1, releases, security), `404.html`, `search-index.json`,
`sitemap.xml`, `robots.txt`, `.nojekyll` and `assets/` (`style.css`, `app.js`, `favicon.svg`).

Features: dark-first theme with a persisted light/dark toggle, responsive sidebar and mobile drawer,
per-page table of contents with scroll-spy, code blocks with language badge and one-click copy,
instant client-side search (`/` or `Ctrl`/`⌘`+`K`), and a live GitHub Releases explorer
(`https://api.github.com/repos/spectre-oss/spectreos/releases`) with graceful fallback links.

## Layout

```text
landing/
├── package.json            # build / preview / test scripts, no dependencies
├── scripts/
│   ├── build.mjs           # site generator (also importable: build({ base, outDir }))
│   ├── serve.mjs           # zero-dependency preview server
│   ├── test.mjs            # validation suite behind `npm test`
│   └── lib/
│       ├── markdown.mjs    # Markdown -> HTML compiler (+ section extraction, highlighting)
│       ├── repo.mjs        # repo facts: component registry, versions, link rewriting
│       ├── layout.mjs      # document shell: header, sidebar, TOC, footer, SVG mark
│       └── pages.mjs       # navigation and page definitions
└── src/
    ├── assets/             # style.css, app.js
    └── content/            # authored Markdown fragments
```

## Content rules

- Do not invent features or numbers. Facts come from the repository documentation, `Cargo.toml`
  files and version files; add or fix them at the source and rebuild.
- Relative links inside rendered source docs are rewritten: links to documents that have a page here
  become site links; everything else becomes a GitHub `blob`/`tree` URL. In authored Markdown use
  `site:docs/libbhoo/` for site pages and `repo:codes/apps/wisp/` for repository paths.
- `codes/shiraz-core` is a separate repository ([spectre-oss/shiraz](https://github.com/spectre-oss/shiraz));
  the site only links to it.
- Component versions on the home and releases pages are read at build time from each component's
  `.version` file (`VERSION` for Spectre NixOS), falling back to `Cargo.toml`.
